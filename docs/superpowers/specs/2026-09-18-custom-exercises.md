# 自定义动作建档与确认保存

用户在聊天中描述动作，固定的 `exercise-authoring` skill 完成识别、查重、必要追问和元信息补全。
它只产出动作草稿；即使用户说“直接保存”，聊天图也没有写入个人动作库的路径。
用户在前端查看草稿和头像后，点击确认，通过独立的保存接口完成入库。

## 元信息与头像

名称、别名、记录方式、主部位、主要及辅助肌群、器械、训练类型、说明、默认重量单位。
名称和记录方式必填；未知分类使用 unknown。模型补全的字段由 inferred_fields 标记。
头像为内置分类 SVG：力量、有氧、活动度、拉伸、其他；元信息提供 key 和受权限保护的 URL。
无需创建动作记录即可展示草稿头像；保存后使用该动作的 thumbnail URL。

## 边界与生命周期

- 草稿仅作为聊天响应的一部分持久化，不能搜索、加入训练或用于训练统计。
- 服务端从当前账号的会话历史提供最近三个未保存草稿，支持自然语言修订；客户端不能伪造。
- `POST /v1/custom-exercises/drafts/{request_id}/save` 只读取已完成聊天的服务端草稿。
- 确认时重新查重、验证分类和账号归属，原子写入个人动作与确认回执；同一草稿重复确认返回原回执。
- 独立的手工表单保存接口接受结构化定义；聊天图不调用任何保存接口。
- 已有标准或个人动作直接返回真实记录，不重复创建；名称歧义时追问。
- 自定义动作按用户隔离，合并为每次请求的临时目录视图，不改变标准快照和校验和。
- 保存后可检索、推荐、计划校验和复盘识别；归档只影响后续选择，保留历史解析与头像。
- 元信息编辑使用版本检查；记录方式不可原地改变。恢复归档通过元信息保存完成。
- 本功能不自动关联旧导入 ID，不改写训练记录；Flutter UI 不在本次后端/网页实现范围内。

## 呈现

网页展示动作草稿、头像、分类与推断字段，以及“确认保存”按钮。成功后展示保存状态和动作详情入口。
动作详情允许编辑或归档当前个人记录。刷新会话恢复待保存/已保存状态；原聊天文字保留当时的表述。
详细请求与返回格式见 docs/api.md 的 Personal exercises and authoring drafts。
