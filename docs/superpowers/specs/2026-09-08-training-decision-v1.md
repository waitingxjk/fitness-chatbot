# 练伴训练决策规范 v1 草案

日期：2026-09-08。状态：复盘、整次方案、目标状态与计划反馈流程已进入本地原型实现与验证。
Boyle 正文阅读暂缓；已加入逐条记录确认与证据门槛；未确认口径、缺少主观用力证据时不开放进展候选。

## 目标与当前范围

建立“训练复盘 → 下一次完整训练方案 → 实际执行 → 调整”的闭环。
当前原型按健康成年人的健身房抗阻训练设计；用户最终目标尚待明确。竞技专项、伤后康复、有氧专项周期不直接套用本规则。

依据分三层：[研究证据 E1–E5](../../knowledge/training/evidence-register.md)、[Boyle 官方节选 B0–B4](../../knowledge/training/michael-boyle-functional-training.md)、下文标记为 P 的产品规则。P 规则是可验证的设计选择，不是论文直接证明的个体处方。

## 共同输入

| 输入 | 来源 | 缺失时的处理 |
| --- | --- | --- |
| 目标、优先动作/部位、训练经验 | 用户明确设定 | 可先做描述性复盘；完整推荐前询问最关键目标 |
| 每周安排、可用时间、器械 | 用户设定及本次补充 | 不编造时长和器械；明确暂定条件 |
| 已完成训练、组明细、单位 | 当前用户的服务器训练数据 | 显示时间范围、截断及同步缺口；不把空库当作没训练 |
| 当前主观状态 | 用户反馈；有记录时使用 RPE/RIR | 不给出伪精确恢复分数；决定是否需要先追问 |
| 当前周期与推荐计划 | 已保存并接受的计划 | 标记阶段未知；区分“建议进入”与“已经处于” |
| 动作元信息 | 审核后的真实目录 | 无标签的动作不用于依赖该标签的决策 |

RIR 表示估计还能完成的次数；RPE 为主观用力程度。二者的量表、测量时间和用户熟悉程度必须记录，不能从“组已完成”反推。

## 复盘协议

P01：默认提供最近 7 天与此前 21 天的对照，并允许用户选周期。这个窗口是产品默认值，不是生理学分界；不足、停训、同步遗漏分别注明。不能用已截断的最近 30 次摘要冒充全量周统计，后续需按用户和日期在数据库计算。

| 维度 | 程序计算的事实 | 解释限制 |
| --- | --- | --- |
| 节奏 | 训练次数、日期间隔、计划完成次数 | 没有保存计划时不计算完成率 |
| 分配 | 部位和动作模式的出现频率、已完成组分布 | 未审核的辅助肌群贡献不套固定比例；不重复计入总组数 |
| 进展 | 同一动作、同一负重口径、可比条件下的次数和负重变化 | 不混比单双只哑铃、kg/lb、自重附加负重或不同机器档位 |
| 调整信号 | 连续表现变化、未完成情况及用户反馈 | 不单凭一次表现下降判定疲劳、伤病或退步 |

每条发现必须包含：结论、关联的训练/组记录、比较口径、可能解释、可执行调整、缺失信息。使用事实、推断、建议三种标签。数值由程序产生，模型不能重算后覆盖事实。

复盘呈现顺序：范围与数据质量 → 2–4 条主要发现 → 保持事项 → 下一次调整 → 一项最关键追问（需要时）。

## 整次训练推荐协议

P02：先结合目标与已接受计划确定候选主题，再用近期执行和当天约束调整。未训练部位可以成为候选，不能简单用“距离上次最久”唯一决定主题。

P03：分别生成延续、增加次数、增加负重、增加组数、降低要求或休息等候选调整。默认先改变一个主要训练变量，减少解释歧义；这是初版控制策略。只有新增体积、提升强度等含义明确后才使用“加量”。

P04：周期状态保存为“已确认计划阶段”与“当前调整建议”两个对象。E5 提供方法背景，但不支持把固定周数或百分比当成人人适用的科学阈值。历史不足时保持未知，不临时编造周期。

P05：先分配训练目的，再选择动作。每个项目保存角色（重点/辅助/补充）、目标、真实动作 ID、组数、次数或时长、负重依据、用力要求、休息和替代条件。

P06：排序先保护本次优先动作，再审查动作之间的局部肌群、握力、腰背稳定与技术要求重叠。E2 是优先级原则的依据；具体“动作 A 影响动作 B”的边必须由可审阅的运动学资料或专业人员确认，不由模型编造精确疲劳百分比。

P07：预计用时必须计入准备、执行、组间休息和器械切换。超时时先减少低优先级内容或选择短方案，不用压缩必要休息伪装成可完成。用时是估计区间，不承诺精确分钟。

P08：动作替换后重新检查目标、技能、器械、时间与负重口径。不能把固定器械标示重量直接迁移到自由重量；E3 提供适用边界。复用熟悉动作是本产品的默认偏好，不宣称所有新动作都不合适。

输出：本次主题和理由 → 按顺序的完整安排 → 负重选择与调整依据 → 时间或器械受限的替代 → 执行后需要反馈的内容。

## 知识和工程边界

- 统计、身份隔离、真实动作匹配、单位和时间检查由程序完成；模型负责解释、交互与受约束的候选方案。
- 推荐方案用独立的 SessionPlan 保存，并关联目标、历史证据和规则版本；实际训练仍由 iOS 创建/修改。
- 现有“搜索最多 2 张、推荐最多 3 张动作卡”继续适用于旧动作检索接口。完整训练应使用独立的计划响应结构，不能偷偷扩张旧卡片协议。
- 训练记录、用户文本和书籍材料都作为数据使用，不能变更身份、权限或系统规则。
- 知识库目前是设计资料；接入时采用经审阅、带版本的规则子集。维持现有暂缓向量 RAG 的决定。
- 方案的接受、替换、跳过和实际完成需留存，供下次复盘比较。拒绝一个方案不能被解释为用户不愿训练。

## 验收与推进

| 阶段 | 交付 | 必须通过的验证 |
| --- | --- | --- |
| 1 | 可追溯的结构化复盘 | 数值与原记录一致；同期比较合理；缺失/截断可见；用户隔离 |
| 2 | 一次训练的完整方案 | 真实动作；器械与时间可行；排序有依据；负重有来源；条件变化能重算 |
| 3 | 计划与执行反馈 | 计划版本可追溯；未完成原因可区分；后续调整回应实际反馈 |

评估集至少包含：记录充分、没有记录、同步缺口、单位混用、重点动作需保护、器械不可用、时间不足、主观疲劳、阶段未知、其他用户数据不可见。自动测试使用合成数据和模型替身；模型质量评估与程序正确性分别记录。

讨论样例见[三份样例](2026-09-08-training-decision-examples.md)。用户在测试页填写个人目标和当天条件，缺失时先追问。具体处方规则仍须经专业审阅和案例评估，不能仅凭“有引用”直接宣布科学有效。Boyle 正文阅读暂不作为当前推进依赖。


## P09：记录确认与进展门槛（本地实现补充）

用户逐条确认记录版本、负重口径、同一器械/幅度/技术条件及最后工作组 RIR。
这些确认独立、可撤回，不修改 iOS 快照；快照修订后重新确认。比较只使用最近两次同条件记录，
最新记录须在十四天内，组数相同、组内次数一致、次数未下降；熟悉量表的最后组 RIR 须在二至六之间，
且最新余力不低于前次。最新无效或未完成记录阻止用更早样本支持加量。

这些是初版保守产品门槛，不是论文证实的生理阈值。满足条件仅支持讨论一次改变一个变量：
每组加一次、加一组，或保留组次并试用器械最小增量；不能直接宣称能力提高或恢复完成。
详细数据契约、冲突与复验机制见 [API 文档](../../api.md#observation-confirmation-and-progression-eligibility)。
