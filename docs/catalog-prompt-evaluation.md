# 全量动作库放入 prompt 的 token 评估

基于 chatbot 本地完整 1,324 条动作，使用 tiktoken 对 `gpt-5.4-mini` 对应的
`o200k_base` 编码实际计数。原始数值保存在 [catalog-token-counts.json](catalog-token-counts.json)。
这是目录文本的输入 token，未包括系统提示、工具 schema、消息封装、聊天历史和本轮请求。

| 目录内容 | 输入 token | 每动作平均 |
| --- | ---: | ---: |
| ID + 中文名，按行 | 18,116 | 13.7 |
| ID + 中文名 + 部位/器械/主要肌群，按行 | 36,634 | 27.7 |
| ID + 中文名 + 第一步操作，按行 | 46,337 | 35.0 |
| ID + 中文名 + 全部操作步骤，按行 | 160,393 | 121.1 |
| ID + 中文名 + 全部操作步骤，紧凑 JSON | 169,664 | 128.1 |
| 原始所有字段，紧凑 JSON | 378,303 | 285.7 |

当前库没有独立 description 字段；这里“完整描述”指将 instructionStepsZhHans 拼接。
第一步操作并不等价于一条高质量摘要，只作为长度参考。属性说明可由现有字段确定性生成，
不消耗模型调用，也不会额外引入事实。

属性行示例：

```text
0289|哑铃卧推|胸部；哑铃；主要训练胸大肌
```

建议先验证“36.6k 全量精简目录 + 模型选择 ID + 本地按 ID 读取完整步骤”。
这样可以先不部署向量检索系统，动作身份和最终卡片仍由本地目录验证。
它仍有检索/读取阶段，但不需要向量 RAG；详细回答阶段只放选中的几条完整动作。

每次模型调用包含一份目录时，目录带来的输入增量分别约为 36.6k 或 160.4k。
现有 LangGraph 一轮聊天有理解和回答两次模型调用，若两次都携带目录，相应增量约为
73.3k 或 320.8k；建议只在选择动作阶段使用全量精简目录。

以上只证明 token 数量，不证明准确率和延迟。前次 3～5 秒的聊天样本没有携带全量目录，
不能直接套用。正式替换前应实测名称搜索、模糊语义、器械限制、多轮指代和无结果情况。
暂缓向量 RAG，尚未将生产 prompt 替换为本方案。

复现（本地计数，不调用付费模型 API）：

```bash
uv run python scripts/count_catalog_tokens.py --output docs/catalog-token-counts.json
```
